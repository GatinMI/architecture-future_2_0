# Агрегаты «Будущего 2.0»

Агрегат - граница транзакционной согласованности: инварианты домена сохраняются только внутри агрегата, «извне» на него воздействуют команды, а меняет он мир через доменные события. Идентификаторы глобально уникальны (UUID/ULID), чтобы события разных доменов связывались без единой базы.

Общие правила:

- Идентичность (ключ) и состояние агрегата живут в базе своего контекста; другие домены получают факт изменения только событием.
- «Удаление» и «правка» - не операции: только статусы и новые версии (аудит по событиям).
- Медицинские результаты (диагнозы, снимки) не покидают контекст ИИ-диагностики в виде данных - наружу уходит только факт и метаданные (см. событие `AiExaminationCompleted`).

## Мастер-данные

### Client (клиент)
- **Ключ:** `client_id`
- **Состояние:** ФИО/наименование, дата рождения, регион, тип (физлицо/юрлицо), статус (active/inactive)
- **Инварианты:** уникальность пары (ФИО + дата рождения + регион) или ключ из реестра; клиент не удаляется - только деактивация; изменения только через команды контекста
- **События:** `ClientRegistered`, `ClientProfileUpdated`

### Employee (сотрудник)
- **Ключ:** `employee_id`
- **Состояние:** роль, клиника, должность, статус
- **Инварианты:** сотрудник одновременно на одной должности в одной клинике
- **События:** `EmployeeRegistered`

## Пациентский поток (клиники)

### Patient (пациент)
- **Ключ:** `patient_id`
- **Состояние:** персональные данные (медицинская зона), привязка к `client_id` (опционально - если человек тоже клиент банка), клиника регистрации
- **Инварианты:** данные неизменяемы - коррекция создаёт новую версию с историей; пациент привязан к клинике регистрации
- **События:** `PatientRegistered`

### Visit (визит)
- **Ключ:** `visit_id`
- **Состояние:** `patient_id`, `clinic_id`, дата/время, статус (scheduled/completed/cancelled), код диагноза (после завершения)
- **Инварианты:** переход статусов только scheduled -> completed | cancelled; завершённый визит имеет ровно один код диагноза; визит принадлежит ровно одному пациенту
- **События:** `VisitScheduled`, `VisitCompleted`

### TreatmentPlan (план лечения)
- **Ключ:** `plan_id`
- **Состояние:** `visit_id`, `patient_id`, упорядоченный список назначенных исследований
- **Инварианты:** план привязан ровно к одному визиту; исследование добавляется только к открытому плану
- **События:** `ExaminationRequested`

## ИИ-диагностика (медицинские данные)

### Examination (исследование)
- **Ключ:** `examination_id`
- **Состояние:** `patient_id`, `visit_id`, тип исследования, статус (requested/in-progress/completed), `model_version`, результат (хранится в изолированной медицинской зоне)
- **Инварианты:** ровно один завершённый результат - коррекция создаёт новую версию; исследование привязано ровно к одному визиту; клинический результат не публикуется во внешние домены
- **События:** `AiExaminationCompleted` (только статус и метаданные, без клинического результата)

## Финтех (банк)

### CreditContract (кредитный договор)
- **Ключ:** `contract_id`
- **Состояние:** `client_id`, сумма, срок, ставка, статус (created/active/repaid/closed)
- **Инварианты:** договор привязан к ровно одному клиенту; платежи принимаются только по активному договору; закрытый договор неизменяем
- **События:** `CreditContractCreated`

### Account (счёт)
- **Ключ:** `account_id`
- **Состояние:** `client_id`, валюта, баланс
- **Инварианты:** баланс не ниже нуля (кроме одобренного овердрафта); счёт принадлежит одному клиенту
- **События:** `AccountOpened`

### Payment (платёж)
- **Ключ:** `payment_id`
- **Состояние:** `account_id` или `contract_id`, сумма, валюта, дата, статус (executed/reversed)
- **Инварианты:** после выполнения неизменяем; возврат - новое событие, а не изменение старого
- **События:** `PaymentExecuted`

## Финансовая отчётность (ГО)

### FinancialPeriod (отчётный период)
- **Ключ:** `period_id`
- **Состояние:** период (месяц/квартал), статус (open/closed), ссылки на снепшоты данных
- **Инварианты:** закрытый период неизменяем; корректировки - «красное сине» или новый период
- **События:** `FinancialPeriodClosed`

## Фарм (новое направление)

### PharmaOrder (фарм-заказ)
- **Ключ:** `order_id`
- **Состояние:** `clinic_id`, позиции, сумма, статус
- **Инварианты:** заказ привязан к ровно одной клинике; после подтверждения неизменяем
- **События:** `PharmaOrderPlaced`

## Медэлектроника (новое направление)

### Device (устройство)
- **Ключ:** `device_id`
- **Состояние:** `clinic_id`, тип, статус (installed/in-service/maintenance)
- **Инварианты:** устройство привязано к ровно одной клинике; телеметрия публикуется только для своего `device_id`
- **События:** `DeviceRegistered` (телеметрия - высокочастотный поток, не попадает в витрину)

## Витрина данных (BI)

Классических агрегатов нет - это read-модели (марты) по доменам поверх ClickHouse, собираемые из событий (Flink - near real-time, dbt - micro-batch). Согласованность eventual: событие доведено до витрины в пределах SLA свежести, инварианты доменов здесь не хранятся.
