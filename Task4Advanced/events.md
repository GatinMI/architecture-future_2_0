# Каталог доменных событий

Единые принципы:

- Событие называется прошедшим временем («Платёж выполнен» / `PaymentExecuted`) - оно фиксирует уже случившийся факт.
- Публикует событие только домен, в котором факт произошёл. Подписчик получает копию и трактует её в своём контексте.
- Схема события закреплена в каталоге (Schema Registry, Avro/JSON Schema); правила совместимости: back/forward compatibility, breaking change - только новая версия.
- Оболочка (envelope) у всех событий общая:

```json
{
  "event_id": "uuid",          // уникальность, дедупликация на потребителе
  "occurred_at": "ISO-8601",   // время факта
  "context": "fintech",        // контекст-источник
  "correlation_id": "uuid",    // сквозной ключ бизнес-процесса (например, визит или договор)
  "data": { }                  // payload события
}
```

- Все подписчики идемпотентны (`event_id` + upsert), поэтому повторная доставка (replay из DLQ) безопасна.

## События целевого состояния

| # | Событие (RU / EN) | Контекст-источник | Семантика (когда происходит) | Минимальный контракт (data) | Подписчики |
|---|-------------------|-------------------|-------------------------------|------------------------------|------------|
| 1 | Клиент зарегистрирован / `ClientRegistered` | Мастер-данные | В мастер-реестре создана карточка клиента | `client_id`, ФИО, дата рождения, регион, тип | финтех, витрина |
| 2 | Профиль клиента обновлён / `ClientProfileUpdated` | Мастер-данные | Изменены реквизиты клиента | `client_id`, список изменённых полей, `updated_at` | финтех, витрина |
| 3 | Сотрудник зарегистрирован / `EmployeeRegistered` | Мастер-данные | Добавлен сотрудник клиники (персонал) | `employee_id`, роль, `clinic_id` | витрина, фарм, медэлектроника |
| 4 | Пациент зарегистрирован / `PatientRegistered` | Пациентский поток | В клинике создана карточка пациента | `patient_id`, ФИО, дата рождения, `clinic_id`, `client_id` (nullable) | витрина |
| 5 | Визит запланирован / `VisitScheduled` | Пациентский поток | Запись на приём создана/подтверждена | `visit_id`, `patient_id`, `clinic_id`, `scheduled_at`, врач | витрина |
| 6 | Визит завершён / `VisitCompleted` | Пациентский поток | Приём завершён, присвоен диагноз | `visit_id`, `patient_id`, код диагноза, `completed_at` | ИИ-диагностика, фин. отчётность, витрина |
| 7 | Исследование запрошено / `ExaminationRequested` | Пациентский поток | Врач назначил ИИ-исследование в плане лечения | `examination_id`, `patient_id`, `visit_id`, тип исследования | ИИ-диагностика |
| 8 | Исследование ИИ пройдено / `AiExaminationCompleted` | ИИ-диагностика | Модель обработала исследование | `examination_id`, `visit_id`, статус (ok/failed), `model_version` | пациентский поток |
| 9 | Кредитный договор создан / `CreditContractCreated` | Финтех | Подписан кредитный договор | `contract_id`, `client_id`, сумма, валюта, срок, ставка, `created_at` | фин. отчётность, витрина |
| 10 | Счёт открыт / `AccountOpened` | Финтех | Открыт расчётный/дополнительный счёт | `account_id`, `client_id`, валюта, `opened_at` | фин. отчётность, витрина |
| 11 | Платёж выполнен / `PaymentExecuted` | Финтех | Платёж проведён | `payment_id`, `account_id`, `contract_id` (nullable), сумма, валюта, `executed_at` | фин. отчётность, витрина |
| 12 | Период отчётности закрыт / `FinancialPeriodClosed` | Фин. отчётность | Период закрыт, отчётность сформирована | `period_id`, период, `closed_at` | витрина |
| 13 | Фарм-заказ размещён / `PharmaOrderPlaced` | Фарм (новое) | Клиникой оформлен заказ в фармкомпанию | `order_id`, `clinic_id`, сумма, валюта, `placed_at` | фин. отчётность, витрина |
| 14 | Устройство введено в эксплуатацию / `DeviceRegistered` | Медэлектроника (новое) | Устройство поставлено в клинику и запущено | `device_id`, `clinic_id`, тип, `commissioned_at` | витрина |
| 15 | Телеметрия устройства / `DeviceTelemetryReceived` | Медэлектроника (новое) | Высокочастотный поток показаний | `device_id`, метрики, `ts` | контекст-внутренние (мониторинг, сервисные SLA); в витрину - только агрегаты |

Примечание по #8: клинический результат (диагноз, снимки) в событие не включается - он остаётся в изолированной медицинской зоне; наружу уходит только факт завершения и версия модели. Визуализация результата - внутри ИИ-сервисов, по которым его открывает врач.

## Мосты совместимости (легаси, временные события)

| Событие | Источник | Семантика | Подписчики |
|---------|----------|-----------|------------|
| `LegacyFinanceUpdated` | CDC-мост (DWH SQL 2008) | Изменение финансовой таблицы DWH, не переехавшей ещё в финтех/ГО | фин. отчётность (до миграции) |
| `LegacyMedData` | ACL-адаптер (ESB Camel) | Медицинские данные из Camel-маршрутов, пока пациентский поток не на бэкбоне | ИИ-диагностика (до миграции) |

Оба события обёрнуты в тот же envelope, помечены `context: legacy-bridge` и живут до вывода соответствующего моста (этапы см. в Task3Advanced).

## Матрица подписок (кто на что подписан)

| Подписчик | Подписки |
|-----------|----------|
| Финтех | ClientRegistered, ClientProfileUpdated |
| ИИ-диагностика | ExaminationRequested, VisitCompleted (+ LegacyMedData до миграции) |
| Пациентский поток | AiExaminationCompleted |
| Фин. отчётность | CreditContractCreated, PaymentExecuted, VisitCompleted, PharmaOrderPlaced (+ LegacyFinanceUpdated до миграции) |
| Витрина | все события #1–14, кроме #8 (медицинская зона) и #15 (сырая телеметрия) |
| Фарм, медэлектроника | EmployeeRegistered, ClientRegistered (мастер-данные для интеграций) |
