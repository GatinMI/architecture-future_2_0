# TCO: текущая и целевая архитектура (3 года)

Сравнение совокупной стоимости владения: As-Is (DWH SQL Server 2008 + ESB Camel +
PowerBuilder/Power BI on-prem) и To-Be (событийная платформа на Yandex Cloud +
витрина + Data Mesh).

## 1. Методика и допущения

- Горизонт: 3 года.
- FTE: ~2,5 млн ₽/год «под ключ» (зарплата + налоги + накладные).
- Ограничение легаси: SQL Server 2008 - EOL, апгрейд DWH неизбежен независимо
  от решения о целевой архитектуре.

## 4. Сравнение и чувствительность

**Базовый сценарий (без новых доменов/регионов):** To-Be дороже на ~18,5 млн ₽
(~9%) за 3 года. Переплата - это разовые затраты на миграцию, которые
концентрируются в 1-м году; с 3-го года годовые затраты To-Be (81 млн) уже
стабилизируются, а As-Is несёт постоянную «налог» за легаси-монолит и растущие
потери аналитиков.

Чувствительность:
- Облако ±30%: итог To-Be меняется на ∓10…13 млн ₽ за 3 года - не меняет вывод.
- Задержка миграции на 6 мес.: +~10 млн ₽ (dual-run дольше + As-Is дольше работает).
- Зарплаты FTE ±20%: влияет на обе модели сопоставимо (в To-Be доля команды чуть выше).

## 5. Сценарий с масштабированием (решающий)

Стратегия компании - 2 новых направления (фарма, медэлектроника) и 2 новых
региона с data residency. Это прямо закладывается в план.

- **As-Is с масштабированием:** каждое новое направление = новый ETL + бизнес-
  логика в DWH (~15 млн ₽/год на домен); региональное дублирование DWH
  (мед. и фин. данные нельзя консолидировать) = ~60 млн ₽ разовых + ~30 млн ₽/год
  эксплуатации. Итого: 207,5 + 75 (год 2) + 45 (год 3) ≈ **328 млн ₽**.
- **To-Be с масштабированием:** новые домены и регионы уже учтены в модели
  (9 + 8 = 17 млн ₽): подключение домена - подписка и марты, регион - новая
  облачная зона. Итого: **226 млн ₽**.

**Вывод по сценарию с ростом: To-Be дешевле примерно на 100 млн ₽** за 3 года,
при этом кривая затрат To-Be растёт линейно (подписка/зона), а As-Is -
суперлинейно (каждый домен и каждый регион - новый ETL/копия DWH).

## 6. Немонетарные эффекты

- **Time-to-market отчёта:** часы/дни → минуты/часы (self-service на витрине).
- **Риск EOL:** вынужденная «аварийная» миграция с SQL Server 2008 снимается
  плановой миграцией на целевую архитектуру.
- **Гибкость:** независимые релизы доменов; новый потребитель - подписка,
  а не новый маршрут/ETL.
- **Комплаенс:** data residency и доступы - через IAM и изоляцию доменов,
  а не через ручные договорённости.

## 7. Итог

По базовому сценарию модели сопоставимы (±10%, разовые затраты на миграцию в
1-м году). Как только компания делает запланированное масштабирование
(новые направления + регионы), целевая архитектура становится заметно
дешевле (~100 млн ₽ за 3 года) и при этом быстрее. Дополнительные деньги
в 1-м году To-Be фактически заменяют обязательную модернизацию DWH в 2-м
году As-Is - т.е. «дороже» только на бумаге.
