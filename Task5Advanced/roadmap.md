# Data Mesh Implementation Roadmap - «Будущее 2.0»

Горизонт: **36 месяцев**.
Роадмап привязан к бизнес-целям компании: запуск финтех-пилота, масштабирование на
критичные медицинские домены, интеграция фарм- и медэлектронных направлений,
расширение в новые регионы (data residency).

---

## 1. Ключевые роли

| Роль | С какого этапа | Зона ответственности |
|------|---------------|---------------------|
| **Data Product Owner (DPO)** | Phase 1 | Владелец data-продукта: определяет требования, SLA, приоритеты; «лицо» данных для потребителей (BI, ИИ, отчётность) |
| **Data Engineer - Platform** | Phase 1 | Событийный бэкбон (Kafka, Schema Registry, DLQ), Flink-джобы, data-озеро (Iceberg/YOS), мониторинг, IaC |
| **Data Engineer - Domain** | Phase 1 | Построение март-слоёв (dbt) конкретного домена, контракты данных, качество |
| **BI-аналитик** | Phase 2 | Self-service отчёты в Superset, семантический слой, дашборды для бизнес-пользователей |
| **Data Steward** | Phase 3 | Контракты данных, каталог метаданных, аудит качества, доступы (RBAC/RLS) |
| **Platform SRE** | Phase 4 | On-call, retention-политики, Tiered Storage, оптимизация стоимости облака, масштабирование |

---

## 2. Этапы

### Phase 1 - Фундамент (0–3 мес.)
**Цель:** подготовленная платформа и роли, готовность к пилоту.

- Определить и назначить DPO для пилотного домена (финтех).
- Развернуть событийный бэкбон: Kafka кластер, Schema Registry, DLQ.
- Разработать стандарт контрактов событий (Avro/JSON Schema, envelope: `event_id`, `occurred_at`, `context`, `correlation_id`, `data`).
- Развернуть dbt-проект с baseline-тестами; определить SLA свежести (например, < 5 мин для горячих потоков).
- Настроить DataHub / каталог метаданных.

**KPI выхода из фазы:** бэкбон uptime > 99.9 %, 100 % событий пилота зарегистрированы в Schema Registry.

### Phase 2 - Пилот: Финтех (3–9 мес.)
**Цель:** доказать работоспособность end-to-end на одном домене.

- Построить data-продукт «Финтех»: bronze/silver/gold марты (договоры, платежи, счета).
- Развернуть Superset-витрину с банками отчётов; семантический слой поверх ClickHouse.
- **Dual-run**: параллельная работа legacy-DWH и нового пути; сверка цифр (расхождение < 0.1 %).
- **Cutover**: перевод банковских отчётов на витрину.

**KPI:** time-to-market отчёта < 1 день (было: 2–5 дней); > 70 % отчётов банка на витрине; 0 критических расхождений в dual-run.

### Phase 3 - Масштабирование на критичные домены (9–18 мес.)
**Цель:** покрыть основные бизнес-домены.

- Data-продукт «Пациентский поток»: операционная аналитика клиник (визиты, загрузка, throughput). **Медицинские данные (результаты ИИ) остаются изолированными.**
- Data-продукт «Финотчётность ГО»: замена legacy-отчётности DWH.
- Внедрить data contracts как обязательный стандарт: каждое новое событие - с контрактом и CI-проверкой.
- Ввести роль Data Steward: аудит качества, управление каталогом, RLS-политики.

**KPI:** > 70 % всех корпоративных отчётов на витрине; SLA-соблюдение > 95 %; стоимость подключения нового отчёта < 1 инженеро-день.

### Phase 4 - Новые домены и регионы (18–36 мес.)
**Цель:** масштабирование в 3 направлениях (продукт, география, данные).

- **Фарма:** data-продукт «Pharma» - заказы, поставки, запасы. Подключение «с первого дня» на событиях, без DWH-ETL.
- **Медэлектроника:** data-продукт «Med Electronics» - агрегаты телеметрии (сырой поток остаётся в домене, в витрину идут агрегаты).
- **Регионы (data residency):** локальные облачные зоны (Yandex Cloud regions) с локальными март-слоями; репликация событий по региональным политикам.
- **Монетизация ИИ:** API-шлюз для моделей ИИ-диагностики; MLOps-практики (реестр моделей, мониторинг дрейфа).

**KPI:** интеграция нового домена < 3 месяцев (было: 6–9 мес. в As-Is); > 90 % отчётов на витрине; SLA-соблюдение > 95 %.

### Сквозная поддержка доменов (18–36 мес.)
- **Platform SRE:** on-call ротация, retention-политики (Tiered Storage для Kafka, lifecycle для Iceberg), стоимость-контроль.
- **Data Steward:** регулярный аудит SLA, quality-отчёты, обновление каталога.

## 3. Привязка к бизнес-целям

| Бизнес-цель | Этап(ы) | Метрика |
|-------------|---------|---------|
| Self-service BI, снижение time-to-market | Phase 1–2 | Отчёт за < 1 день вместо 2–5 дней |
| Финтех-интеграция (купленный банк) | Phase 2 | > 70 % банковских отчётов на витрине |
| Масштабирование на мед. домены | Phase 3 | SLA > 95 %, изоляция мед. зоны |
| Новые направления (фарма, медэлектроника) | Phase 4 | Подключение < 3 мес. |
| Региональная экспансия / data residency | Phase 4 | Локальные зоны, локальные марты |
| Монетизация ИИ | Phase 4 | API-шлюз, MLOps |
| Снижение TCO / снятие риска EOL | Phase 2–4 | ТCO-модель (tco-analysis.md) |
