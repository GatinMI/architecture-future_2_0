# Расширенный технологический радар «Будущее 2.0»

Радар описывает целевой технологический ландшафт и архитектурные подходы
для перехода от текущей схемы (DWH на SQL Server 2008 + ESB Camel +
PowerBuilder/Power BI) к слабосвязанной событийной платформе.
В отличие от классического техрадара, здесь наряду с технологиями учитываются
**архитектурные паттерны** и **инженерные практики**.

Кольца (от центра наружу):

- **ADOPT** - ядро платформы, используется как стандарт во всех доменах.
- **TRIAL** - активно внедряется в пилоте и масштабируемых доменах, решение зафиксировано, но ещё не доведено до полной зрелости.
- **ASSESS** - оценивается для конкретной задачи, пилотируется точечно.
- **HOLD** - не внедряется; существующее использование зафиксировано и планируется к выводу/изоляции.

Цветовое кодирование категории: синий - паттерн/подход, зелёный - технология,
оранжевый - платформа, красный - практика.

## ADOPT

| Пункт | Категория | Обоснование статуса |
|-------|-----------|---------------------|
| Событийная архитектура (EDA) | паттерн | Фундамент целевого состояния: домены публикуют события в бэкбон, потребители подписываются независимо. Заменяет синхронные Camel-маршруты (Task 4, justification). |
| Apache Kafka + Schema Registry | технология | Событийный бэкбон: горизонтальное масштабирование по партициям, каталог схем с правилами совместимости, DLQ для отказов. |
| Yandex Cloud | платформа | Единая облачная площадка: managed-сервисы Kafka/ClickHouse, YOS, VMS, IAM/OIDC, мониторинг. Убирает on-prem-зависимость. |
| dbt (медальонные трансформации) | технология | Standard-слои (bronze/silver/gold) над озером; воспроизводимые трансформации, тесты качества и lineage. |
| Self-service BI (Superset) | паттерн | Аналитики строят отчёты сами на мартках витрины; снимает «часы ожидания» и ручной ETL под каждый отчёт. |
| Terraform + GitLab CI/CD | практика | IaC и воспроизводимый деплой инфраструктуры (Task 1/2); версии окружения, код-ревью изменений. |

## TRIAL

| Пункт | Категория | Обоснование статуса |
|-------|-----------|---------------------|
| Data Mesh (методология) | паттерн | Организация данных вокруг domain-owned «data-продуктов» с DPO и контрактами. Внедряется по роадмапу (roadmap.md); в пилоте - финтех. |
| Apache Flink | технология | Near real-time агрегация событий в марты витрины; горячие потоки без загрузки OLTP. |
| Yandex Managed ClickHouse | технология | OLAP-сервинг витрины: колонное хранение, быстрый OLAP-анализ сотен ТБ в сжатом виде. |
| Data-озеро: Iceberg + YOS | технология | Дешёвое холодное хранение сырых событий (сотни ТБ) с версионированием и time-travel. |
| Kafka Tiered Storage | технология | Удлинённое хранение топиков без утилизации: replay, аудит, отладка расхождений цифр. |
| Качество данных: dbt tests + SLA | практика | Тесты непротиворечивости и SLA свежести на мартках; алерты при сбое SLA. |

## ASSESS

| Пункт | Категория | Обоснование статуса |
|-------|-----------|---------------------|
| MLOps (реестр, мониторинг моделей) | технология | Контроль версий и дрейфа моделей ИИ-диагностики; оценивается по мере зрелости ИИ-контекста. |
| Managed YC vs self-hosted | платформа | Выбор между управляемыми и self-hosted сервисами (Kafka/Flink) по цене и SLA - оптимизируется по данным реального использования. |
| GraphQL API витрины | технология | Альтернативный интерфейс доступа к витрине для приложений; оценивается при росте числа потребителей API. |
| Альтернативный OLAP: Pinot / Yandex DW | технология | Резервные OLAP-движки на случай ограничения ClickHouse по нагрузке/цене. |
| Data contracts на платформе | практика | Формализованные контракты публикации событий с автопроверкой при CI; усиление Schema Registry. |
| Vector DB (RAG) для меддокументов | технология | Поиск по медицинским документам/протоколам; оценивается отдельно в мед. зоне (не в витрине). |

## HOLD

| Пункт | Категория | Обоснование статуса |
|-------|-----------|---------------------|
| ESB Apache Camel | технология | Легаси ESB: точечные синхронные маршруты; выводится по мере перевода доменов на события (ACL-мост до 3-го года). |
| DWH SQL Server 2008 | технология | EOL: нет поддержки и патчей. Миграция обязательна; выводится в пользу событийной витрины. |
| Power BI как основной BI | технология | Заменяется Superset-витриной (self-service); Power BI - legacy, не развивается. |
| Точечные синхронные интеграции | паттерн | Отказ от point-to-point синхронных связок: один «тормозящий» потребитель деградирует источник; заменяется асинхронными подписками. |
| PowerBuilder (вне мед. зоны) | технология | Устаревший операторский интерфейс; сохраняется только в изолированной мед. зоне, вне экосистемы не развивается. |
| ETL в DWH как единственный путь данных | паттерн | Запрет «все данные только через DWH»: новый домен больше не требует DWH-трансформации (требование руководства). |
